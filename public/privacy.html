Privacy, explained.

This overview describes the current SecretDrop implementation. It explains what the application stores and the limits of its deletion features.

Your message and password

Encryption and decryption run in your browser. In the normal app flow, the API receives encrypted text, an initialization vector and a salt, rather than your readable message or password. Passwords are not recoverable through the service. Weak passwords can still be guessed; use a long, unique password and share it separately from the recipient link.

Data stored by the application

The Supabase PostgreSQL database stores the encrypted message, message code, creation and expiry timestamps, burn setting, unlock-attempt count, and hashed deletion or burn credentials where applicable. The API also stores its connection's remote IP address, which may be a hosting proxy address. Hosting providers may process request information such as IP addresses, requested URLs and operational logs.

How long data remains

Messages stop being available through the API after the selected expiry time. Expiry is access enforcement: there is currently no scheduled purge of expired rows. Confirmed Burn After Read and sender-authorized deletion remove the live database record. This does not guarantee immediate erasure of provider backups or logs, and does not remove copies held by a recipient.

Sender deletion and private links

The sender receives a private management link containing a deletion credential in the URL fragment. The app sends that credential to its API only when manual deletion is requested. The recipient share link does not include it. Keep the management link private and save it if you want to delete later. Earlier messages created before sender credentials were introduced have no recoverable sender deletion key.

Service providers

The frontend and API are hosted on Vercel, and encrypted records are stored in Supabase PostgreSQL. Provider handling is described in the Vercel privacy policy and Supabase privacy policy.

Advertising and browser storage

The app currently includes no AdSense ad code or advertising trackers. It does not use an advertising consent banner because advertising has not been enabled. Any future advertising integration will need updated disclosures and the applicable consent controls before activation. The app keeps form state in memory and places sender management credentials in the address-bar fragment; your browser may retain URLs in its history.

Before you share

Use the service only for content you have permission to share. Anyone with the recipient link and password can decrypt an available message. Anyone with the private sender link can delete it. SecretDrop cannot prevent recipients from copying or photographing a revealed message.
